BACKEND / REST API

Principles I use when designing REST APIs.

A practical note from my ongoing journey of building and understanding backend systems.

Start with the contract

Resources, request shapes, response shapes, status codes, and error formats should be understandable before implementation details take over.

Validate at the boundary

Reject invalid input close to the API boundary so application rules remain focused on valid data.

Treat errors as part of the API

Consistent error responses make clients easier to build and services easier to debug.

Authentication is not authorization

Identity and permission are separate concerns. Keeping that distinction clear improves system design.

Keep business rules out of handlers

HTTP handlers should coordinate transport concerns while application and domain rules remain independently testable.
